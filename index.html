Three decisions that shape the backend

01 / CONSISTENCY
Data and events commit together.

Incident changes and outbox records share one database transaction. A separate publisher waits for Kafka acknowledgement. Delivery is at least once, so consumers still need idempotency.

02 / CORRECTNESS
Old analysis cannot overwrite new evidence.

Evidence revisions and request IDs bind callbacks to a snapshot. Stale results receive HTTP 409; repeated callbacks are safe. The worker writes through the API rather than owning database credentials.

03 / HUMAN CONTROL
Analysis proposes. A responder decides.

Bounded, validated model output stays advisory. A deterministic heuristic path works without an AI key. The system never performs automatic remediation.

Failure cases, validation limits & what I’d change
What can break

Kafka may accept a message before the publisher commits, producing a duplicate after restart. New logs can also make an in-flight analysis stale. The design handles repeat effects and rejects stale writes; it does not promise exactly-once delivery.

What blocked validation

Initial local checks were limited by Docker and registry access. GitHub Actions later exercised the real database, cache and broker. The full observability stack and a live AKS deployment were not validated.

What I’d change next

Add provider-call cost deduplication, replace in-memory summary aggregation as data grows, and add tenant isolation before considering a public multi-user deployment.

Problem & key decisions

  1. SQLite is the durable queue. Redis only wakes workers; losing a notification does not lose the job.
  2. Leases fence stale workers. A 60-second lease renews during work. A worker that loses ownership cannot commit new progress.
  3. Approval is persisted state. The executor enforces plan and media review gates. Model output cannot bypass them.

Failure cases & next changes

A crash between a provider call and a checkpoint can repeat the paid call. Recovery is at least once. Missing or corrupt media invalidates downstream stages and reopens review.

I’d add provider idempotency where supported, isolate each user’s jobs, and move media workers off constrained web hosting. The current app is a portfolio workflow, with no built-in user isolation.
